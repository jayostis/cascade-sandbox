# @the-cascade-protocol/sandbox

Pretend hospitals that speak SMART on FHIR, for developing and testing an app's
connection to a hospital with no account, no vendor's sign-in page and no
network.

Install it as a git dependency pinned by commit (it builds itself on install):
`npm install --save-dev github:jayostis/cascade-sandbox#<commit>`.

A hospital is one function, `(request: Request) => Promise<Response>`, made from
that hospital's data and answering at its FHIR base URL: discovery
(`.well-known/smart-configuration`), the authorize endpoint (a sign-in page, or
an automatic approval), the token endpoint, and FHIR reads, searches and
histories by patient, as of a date. It uses only `Request`, `Response`, `URL` and WebCrypto, so it runs
unchanged in Node and in a browser.

```ts
import { demoHospital } from "@the-cascade-protocol/sandbox";
import { loadHospital } from "@the-cascade-protocol/sandbox/node";

const north = demoHospital(await loadHospital("cascade-north"));
const response = await north(
  new Request(
    "https://cascade-north.demo.invalid/fhir/.well-known/smart-configuration",
  ),
);
```

Options: `hospital` and `patients` (what `loadHospital` returns),
`authorizeUrl` (the sign-in page's address, by default `<base>/authorize`),
`autoApprove` (a patient id: sign in as them with no page), `now` (the clock
codes and tokens expire by) and `asOf` (the world's date, a FHIR instant such as
`2024-02-01T00:00:00Z`: the hospital answers with its records as they stood
then; with none, with each record's latest version).

## Failing on purpose

To test an app's error handling, add `simulate_error=<name>` to the authorize request, or pick "Simulate a failure" on
the sign-in page. `token_invalid_token` and `token_invalid_scope` fail the token request (401); `request_invalid_token`
and `request_expired_token` issue a token that every record request then refuses (401). An unknown name redirects back
with `error=invalid_request`. The names and answers are smart-launcher-v2's; see [`rulings.md`](rulings.md).

## Versions and the world's date

A patient file is a FHIR R4 Bundle of one of two types:

- **`collection`**: plain records, one entry `{ "resource": … }` each. A plain
  record has one version, is there at every date, and is served exactly as
  written, never stamped with a version.
- **`history`**: each entry is one version of a record, with `request` and
  `response`; `response.lastModified` is when it was recorded. A deletion is an
  entry with no `resource` and a `DELETE` request.

With `asOf`, search, read, vread (`<type>/<id>/_history/<vid>`) and instance
history (`<type>/<id>/_history`, with `_since` and `_at`) answer with each
record's latest version recorded at or before it. A record deleted by then reads
as 410; the sign-in page says the date and lists only the patients there then.
`versionsOf` and `recordsAt` read a patient file the same way, and bad data or a
bad `asOf` throws `HospitalDataError` with its reason. A deletion never shows in
a pod: a pull carries what is there, so a record deleted at the hospital stays
in the pod as it was last pulled (arrival A8).

[`rulings.md`](rulings.md) records each choice the hospital makes against FHIR
and SMART, with the text it follows and the test that pins it. `npm run
validate:data` (Docker, a network) checks every version of every record against
FHIR R4 and US Core with the HL7 validator.

## Not security

This hospital is pretend, and nothing about it protects anything:

- codes and tokens are signed notes, HMAC-SHA256 under a key that is in this
  package's data for anyone to read;
- a code can be exchanged more than once, and nothing can be revoked;
- any client ID is accepted, and the redirect URI is never checked against a
  registration.

That is what lets it keep no state between requests: a service worker that
restarts in the middle of a sign-in loses nothing.

## The data

A hospital is its settings; a person is a folder of who they are and what each
hospital holds of them. Both are files with no code:

```
hospitals/
  cascade-north/
    hospital.json        name, sign-in page colour (optional, dark), FHIR base, page size, key, types, references left out of searches
people/                  the people generated by Synthea
  <person>/
    person.json          who they are: name, birth date, gender
    sources/<hospital>/
      fhir.json          their record at that hospital, as a FHIR R4 Bundle (collection or history)
vocabulary/people/       the hand-written people, the vocabulary's, in the same layout
```

A hospital's patients are every person with a `sources/<its id>/fhir.json`,
under the Patient id there. Every load checks each source's Patient against its
`person.json` on name, birth date and gender, and refuses a disagreement the
person does not declare.

Every name and record is synthetic, and comes in three kinds.

- **Hand-written, for the tests**, in `vocabulary/people/`: a copy of the
  vocabulary's `people/` at the commit `vocabulary.json` pins. Nobody edits it;
  `npm run people -- <vocabulary checkout>` writes it again from the pin, and
  `npm run people -- --check <vocabulary checkout>` fails where it differs.
  Rowan Ellery Marsh is a patient at both hospitals, under a different patient
  id and different record ids at each; Tobias Fenn is at North only. North
  leaves one of Rowan's encounters out of its searches, and serves it only when
  read by id.
- **Story people, for grading an analysis**, also the vocabulary's: five small
  patients at North, each with a planted change in their labs after a
  medication starts or stops, or none, and the written answer in
  `expected/story.json`, which no hospital serves, read through `loadStories()`
  from `@the-cascade-protocol/sandbox/node`. Each states what changed after the
  medication, never that the medication caused it. Tamsin Vale is also a C-CDA
  document, whose records the matcher joins to the FHIR copy by their shared
  NDC (and, where the pod holds a drug products table, their RxNorm code).
- **Generated by Synthea, for the demo**, in `people/`: ten years of visits,
  chronic conditions, medications, labs and vital signs. Blanche Hermiston is at
  both hospitals, Eliseo Krajcik at North and Bertie Hackett at South.
  [`synthea/README.md`](synthea/README.md) says how they were made and how to
  make them again.

[`people/NOTICE.md`](people/NOTICE.md) carries the notices for the generated
people's codes; `vocabulary/people/README.md` carries the hand-written ones'.

## A real address

`serveDemo(hospitals)` from `@the-cascade-protocol/sandbox/node` listens on
`127.0.0.1` at a port the system picks and resolves `{ origin, setWorldDate,
close }`. `demoRemapFetch(origin)` is a `fetch` that sends a request for
`https://<id>.demo.invalid/<rest>` to `<origin>/<id>/<rest>` with a `Forwarded`
header naming the host asked, and every other request to the real `fetch`. The
listener rebuilds the address from that header, so each hospital answers at its
own base and every link in its records names `<id>.demo.invalid`. The sign-in
pages are the listener's own, `<origin>/<id>/authorize`, which a browser can
open; a request with no `Forwarded` header gets nothing else (a 404), and one
whose host is not the path's hospital is a 400.
